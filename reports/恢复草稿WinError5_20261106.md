# 恢复草稿写入 WinError 5（2026-11-06）

## 现象

工作台启动后，登录卡片上直接显示一段 Python 异常文本：

```
[WinError 5] 拒绝访问。:
'F:\papercutter\runtime\server_recovery_drafts\10d32d79c8a55353\BADA11D3FD6CA43F9A6D2A71EFA5DCD4D.tmp'
->
'F:\papercutter\runtime\server_recovery_drafts\10d32d79c8a55353\BADA11D3FD6CA43F9A6D2A71EFA5DCD4D.json'
```

现场（截图 14:25:38）：

- 同名 `.json`（125,248 字节）与 `.tmp`（125,264 字节）**同时存在**，
  同一分钟写入，`.tmp` 大 16 字节 —— 正好是加上 `"synced": true` 后的体积。
- 说明：**保存到服务器这一步成功了**（否则不会有 `synced` 标记），
  失败的是"把本地草稿标记成已同步"这最后一次替换。

## 根因

`desktop_annotation/paperflow_annotation_api.py` 的 `_library_request`：

```python
temporary = target.with_suffix(".tmp")   # 固定名字，所有线程共用
temporary.write_text(...)
os.replace(temporary, target)
```

三个问题叠在一起：

1. **临时文件名固定**。自动保存每秒触发约两次（日志 14:25:20~14:25:34 共 16 次
   "已保存 14 个标注到内存"），两个请求线程同时写同一个 `BADA….tmp`：
   一个写出去了，另一个正在写入，前者去做 `os.replace` 就会撞上被占用的句柄。
2. **失败没人接**。这段没有 try/except，`OSError` 直接冒泡到 `do_POST`，
   整个 save-cache 请求变成失败响应，前端判定"保存失败"。
3. **失败留垃圾**。抛错后 `.tmp` 留在盘上，下次也没有清理。

本地复现：把目标 `.json` 设为只读再调 `_write_recovery_draft`，报错文本与截图
**逐字一致**（`[WinError 5] 拒绝访问。: 'xxx.tmp' -> 'xxx.json'`）。

## 影响面

- 服务器上的标注**已经保存成功**，数据没丢。
- 员工侧看到的是"保存失败"，会重试、会以为白干；如果此时退出，
  本地草稿的 `synced` 标记没写上，下次打开会提示"有未同步草稿"。
- 属于本地兜底机制把主流程拖下水，不是服务器或审核网站的问题。

## 修复

`paperflow_annotation_api.py`：

- 新增 `_write_recovery_draft(target, payload)`：
  - 临时名带 `进程号-线程号`，`<book>.json.<pid>-<tid>.tmp`，线程之间不再互踩；
  - `RECOVERY_DRAFT_LOCK` 串行化同一进程内的替换；
  - `except OSError` 只打一行日志，**不再抛**（草稿是兜底，不是保存主链路）；
  - `finally` 清理临时文件。
- 两处调用点（save-cache 前置写草稿、成功后标记 `synced`）都改走它；
  标记前先兜住草稿读取失败。
- `PAPERFLOW_BRIDGE_REVISION` → `recovery-draft-20261106`（两处同步：
  `paperflow_annotation_api.py` 与 `electron/main.js`），否则 Electron 会复用旧进程。
- `tests/portable_acceptance.py` 的桥版本断言改成读 `main.js` 比对，
  以后升桥版本不用再改验收脚本。

测试：`tests/test_recovery_draft.py`（正常写入、只读目标不抛、6 线程 × 30 次并发）。
全量 **924 项 OK**。

## 还要注意的两件事

1. **这条错误显示在登录卡片上**：`refreshIdentity()` 刷新登录状态失败时，
   会把最后一条 `error.message` 直接写进登录框的提示位
   （`company-review.js:72` + `:91`）。所以一次后台保存失败，看起来像是"登录报错"。
   这个展示口径本身也值得改，但优先级低。
2. **14:25:48 有一次真实的保存失败**，与本次无关：
   `审核中心拒绝请求：服务器版本已更新，请重新打开教材后继续，未覆盖服务器标注。`
   即本地 `project_revision` 落后服务器（服务器上已到 131）。
   处理方式：在工作台里重新打开这本教材再改。
   本机草稿目录下有 3 个账号哈希子目录，说明这台机器被多个账号用过，
   同一本书可能被两个身份先后推过版本 —— 这是版本冲突的常见来源。

## 生效范围

- 本机（源码运行）：重启工作台即可，Electron 会因 revision 变化重启桥服务。
- 员工电脑：需要重发客户端更新包。网站当前那版
  `20261106-1400-client-cleanup`（14:07 发布）**不含**此修复。
