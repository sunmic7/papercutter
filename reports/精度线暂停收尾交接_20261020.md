#### 陪跑现场的三个预期值（照抄，勿当缺陷上报）

在 105 条记录的工程上实测（内存副本，磁盘未动）：

| 指标 | 跑前 | `enrich-prepare` 后 | 性质 |
|---|---|---|---|
| 有快照 | 0 / 105 | **105 / 105** | ✅ 补建生效 |
| `blocked` | **105** | **0** | ✅ 幂等（二次调用 `{'frozen':0,'skipped':105}`） |
| `todo` | 0 | **105** | ✅ **正确**：这些题确实从未补全过 |
| `l2_ratio` | 1.0 | **仍是 1.0** | ⚠️ **真实值，不是没生效、不是算错** |

- **`l2_ratio` 为什么不动**：该工程 `pairs=0`，每条记录都命中 `pair_fail` → 按设计就是 L2。**"未配对工程 100% L2"是正确的真实值**。
- **待办 0→105 是正确行为**，与已修的"升级重冻结不置 `pending`"是**两件不同的事**：
  - 升级重冻结 = 内容哈希没变、AI 结果仍有效 → **不该**新增待办（已修）；
  - 从未补全 = 真的没跑过 → **必须**进待办（正确行为）。
- `blocked → 0` 与 `todo → N` 是**同一批记录的迁移**，不是"问题变多"。
  **断言写法**：`blocked_after == 0` 且 `todo_after >= todo_before`（迁移守恒），
  **不要**断言"todo 应该减少"。
- 现场文案必须提前说明这两条，否则会被报成缺陷，而这类误报最难解释。
- **计数口径**：分级只算 `region_role=='question'` 的记录（该工程 105 条）；"全部 questions" 是 106 条，差额 1 条非题目角色记录。引用数字一律按 **105/105**。
- **不变量**：`blocked` + `todo` 合计 = 总题数（分流只是换桶，不是增减）。
- **P2 收窄**：`l2_ratio` 失真**只发生在"已配对却仍无有效快照"的记录**上；未配对工程全 L2 是设计使然，不是口径残留。
