# 实时样例题库：单题够格就产出 JSON（2026-11-06）

## 为什么要做

原来的生成只有一条路：整本教材**所有页面**被审核员逐页 `approved` → 该次提交状态变成
`reviewed` → 最后一页通过时自动入队 → 后台线程生成 `versions/<version>` + `current.json`。

也就是说，标注员把一道题的题图、题干、答案、解析、难度、知识点全填对了，只要这本书里
还有一页没审，他就看不到这道题的 JSON。用户要求改成：**某一道题自己够格，就能先生成这一题的 JSON**。

## 现状拆解：书级门禁 + 题级过滤

| 层 | 判据 | 位置 |
|---|---|---|
| 书级 | 全部页面 `approved`，`submissions.status='reviewed'` | `decide_page` / `_queue_delivery_job` / `generate_delivery` |
| 题级 | 题图 / 题干 / 选项 / 答案 / 解析 / 难度 / 知识点 / 题型词表 / 题答配对 / 整页图剔除 / 包内重复 | `_k12_validation` + `_write_k12_delivery` |

题级本来就是"够格才收、不够格单题丢弃"，真正卡人的只有书级。所以这次**不动正式交付的
任何一道闸**，另开一条独立的草稿链路。

## 实现

### 引擎（`review_tools/delivery_workspace.py`）

`sync_delivery_workspace()` 新增 `output_root` 参数：同一本工程可以写到不同根目录。
默认行为不变（不传就用 `delivery_root(project, runtime_root)`）。

### 服务端（`online_review_beta/central_library.py`）

- `READY_SAMPLES_DIRNAME = "ready_samples"`、`LIVE_VERSION = "live"`、去抖 20 秒。
- `sync_ready_samples(actor, book_id)`：授权后对**最新工程**（不是审核冻结快照）重算：
  1. `_bind_delivery_source_roots()` 把员工上传时剥掉的原图根绑回服务器扫描件；
  2. 工程复制到 `ready_samples/project.json` 再算——`sync_delivery_workspace` 收尾会回写
     工程文件补 `delivery_id`，直接跑在员工正在标注的工程上会和保存抢同一个文件；
  3. `sync_delivery_workspace(..., materialize_all=False, output_root=<book>/ready_samples)`；
  4. 写 `ready_samples/ready.json`（revision / ready_count / rejected_count / 原因 / 同步时间）。
- `queue_ready_samples(book_id)`：保存后 20 秒去抖，后台线程每 5 秒扫一次。`operate()` 的所有
  写操作、`sync_project_snapshot()`（员工上传工程）都会调用它。
- 身份库与正式交付**同一个** `delivery_identity.sqlite3`：草稿发出的 id 在正式版会被复用，
  不会出现"同一道题两个 id"，跨批次去重照旧。

### 接口（`server.py`）

| 接口 | 说明 |
|---|---|
| `GET /api/deliveries/<book>/samples?version=live` | 读草稿，标注员可读**自己**的书；标注员仍进不去已发布版本 |
| `POST /api/deliveries/<book>/samples-sync` | 手动重算，返回 `ready_count` / `reason_summary` |
| `GET .../sample-image?version=live&path=images/...` | 题图，路径校验与正式版同一套 |
| `GET /api/deliveries/<book>` | 文件清单**不列** `ready_samples`（它不是交付物） |

没有正式版本时，"预览内容"自动落到实时题单；有正式版本时默认仍看正式版。

### 前端（`static/`）

- 生成JSON 每行多一个「实时题单」入口；教材详情「最终交付」页也加了一个（标注员没有提交过
  审核、列表里没行时，仍能从教材详情进去）。
- 版本下拉第一项是「实时样例题库 · N 题」，标题栏显示"未经审核 · 已有 N 题达到交付条件"，
  另有「立即刷新」按钮（超时放到 180 秒，首轮裁图较慢）。
- 页头说明与帮助文案同步改写。

## 已知边界

1. **草稿占磁盘**：`ready_samples` 会把题目/答案裁图与 k12 题图各存一份。一本书多出来的体积
   大致等于一次正式交付的量。测试期可接受；要清理直接删目录即可，下次保存自动重建。
2. **后台重算按整本走**：每本书最多 20 秒一次全量重算（不重裁已有图）。多本书同时标注时
   CPU 会短暂抬升。
3. **草稿不是交付**：不进 `versions/`、不写 `current.json`、不在交付文件清单里，甲方侧无感知。
4. 教材还没上传过工程时点「实时题单」会提示"该教材还没有提交过标注工程"，不是崩溃。
