## 3. 补全流水线（T01–T03）机制速览

### 3.1 判定层
- 三条级别 `L0 / L1 / L2`，`L0` = 可直接交付，`L2` = 必须人工复核。
- 配对判定 `pair_ok = path_match is True AND score >= 180 AND margin >= 80`；
  `display_confidence` **只用于展示**，不参与判定。
- 关键设计：**没有有效快照的记录不算"待办"而算 `blocked`**，两个桶互斥，避免同一道题被数两次。

### 3.2 快照
- `build_snapshot()` 产出：`bbox / text / options / answer / answer_ids / answer_source /
  shared_context_* / continuations / illustration_boxes / profile / 版本三元组 / page_sha1`。
- `hash` 是内容哈希，`snapshot_id = hash[:16]`。
- **`page_sha1_status`（`ok` / `unavailable`）是非权威诊断位，不进哈希**——
  它的作用是把"图没变"和"读不到图"分开。读不到图时 `freeze_or_invalidate` 会保留旧指纹，
  避免离机审查整本失效。
- `answer_source` 三态：`paired` / `manual` / `missing`。

### 3.3 三个入口
| 入口 | 行为 |
|---|---|
| `_save_page_enrich` | 题目页 accepted → `freeze_page`；未 accepted → 只重算级别；答案页 accepted → `refresh_answer_segment` 回写"答案后到" |
| `_enrich_prepare` | **入口无条件先跑 `rebuild_missing()`（遍历全部页）**，再下发题图候选 |
| `_enrich_status` | 只读统计：`level_stats / review_summary / enrich_summary / todo / blocked / snapshot_health` |

- `rebuild_missing` 幂等：已有有效快照的直接 `skipped`，不重写 `created_at`/`hash`。
- 总开关 `PAPERFLOW_ENRICH`（默认 `1`）；置 0 时三条 enrich 路由返回 `{"ok": false, "disabled": true}`。

## 6. 本轮的两个决策

### 6.1 T06（B→V 重构）——不做

设计文档在 `reports/切分算法改造设计_20261020.md`（55KB / 11 节），核心是
把判定顺序从"先按 x 切、再补编号"翻成"先定编号归属（B 系列）→ 再判能否竖切（V 系列）"。
架构师实测推翻了原假设：本案 `any(boundary['side_by_side']) == False`，
`_split_side_by_side_minors()` **根本没触发**；真实病因是 suspects 通道把
`2.7+0.2=` 这类小数算式提升成编号。

否决依据：
1. **收益上限 22%**：它只覆盖口算/横排算式一类，27 个漏切里最多动 6 个；
2. **主矛盾不在这里**：15/20 页是「整页兜底块」，V 系列一个都治不了；
3. **成本是主干级**：动 `cut_questions_v4.py` 的判定主链 + 需要 §9 解冻桥服务保存路径；
4. **风险不对称**：设计自身定了 RB1/RB3——召回一点都不能掉，回归面却是全部版式。

设计文档里的 Q1（`minor_extra` 口径）、Q3（V-B 编号左缘 28%）只影响已放弃的 V 系列，
**不再是阻塞项**。

### 6.2 F-1——已落地（`703855f`）

`cut_questions_v4.py` 新增：

```python
_ARITHMETIC_ONLY_RE = re.compile(r'^[\d.()（）+\-*/×÷=＝<>≤≥−－]+$')
_ARITHMETIC_OPERATORS = '+-*/×÷=＝<>≤≥−－'   # 含 −(U+2212)、－(U+FF0D)

def looks_like_arithmetic_expression(text):
    compact = re.sub(r'\s+', '', str(text or ''))
    if not compact or not _ARITHMETIC_ONLY_RE.match(compact):
        return False
    return any(op in compact for op in _ARITHMETIC_OPERATORS)
```

suspects 救援通道（`find_minor_boundaries` 内）加两个条件才拦截：

```python
arithmetic_fragment = (
    re.match(r'^[0-9]{1,2}[\.．][^\s]', text) is not None   # 点后紧邻非空白
    and looks_like_arithmetic_expression(text)              # 整串就是算式
)
```

行为差异（4 条单测锁定，`tests/test_smart_cutter.py` 150 → 154）：

| OCR 文本 | 算式 | 点后紧邻 | 结果 |

| `10.67−4.07=` | ✔ | ✔ | 拦截 |
| `2. 7+5=` | ✔ | ✘（点后有空格） | 保留（真题号） |
| `2.0.42的计数单位是` | ✘ 含汉字 | ✔ | 保留（救援照旧） |
| `1.6路公共汽车` | ✘ | ✔ | 保留（走 `route_number` 分支） |
