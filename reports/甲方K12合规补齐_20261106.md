## 一、这一轮到底改了什么

只改交付契约层与标注入口，**字段名、文件名、阈值、JSON 结构一律未动**。

### 1. N3 词表闸（`review_tools/delivery_workspace.py`）

原来 `difficulty="3"`、`question_type="火星题"` 会原样透传交付。现在逐项落表，越界即拒收：

| 字段 | 允许值 | 来源 |
| --- | --- | --- |
| `language` | `zh` / `en` | N3 注释 |
| `stage` | 小学 / 初中 / 高中 | N3 注释 |
| `grade` | 一年级…六年级、七年级…九年级、高一…高三 | N3 注释「一年级/七年级/高一等」 |
| `subject` | 数学、语文、英语、物理、化学、生物、历史、地理、道德与法治、科学、信息技术、政治 | N3 + D3 列举 |
| `question_type` | 选择 / 填空 / 判断 / 计算 / 证明 / 实验探究 / 阅读理解 / 材料分析 / 综合应用 | N3 注释 |
| `difficulty` | 基础 / 中等 / 困难 | N3 注释 |

书级字段直接复用 `review_tools/book_meta.py` 的 `STAGES / GRADE_NAMES / SUBJECTS / LANGUAGES`——
那里本来就是"UI 下拉与交付校验必须同源"的唯一口径，不再另立一套。

空值仍由原来的必填项检查报，值域闸只看"填了但填错"，避免一条错报两条。

### 2. H3⑬ PII 匿名化

手机号、邮箱、身份证、QQ/微信账号统一替换为小写 `x`，作用在题干、选项、答案、解析四个字段上。
顺序是**先邮箱后手机号**——否则邮箱里的数字段会被手机号规则提前打散。

### 3. H3③ 整页截图二次复查

候选阶段 `illustration_candidates.hard_reject()` 已经判过 `page_like`，但那只把候选标成"灰色不可采用"。
人工把整页框标成 `image-area` 之后，它照样会进 `illustrations`，原来的交付闸只跳过 `image_kind=='ignore'`。

现在按**图框面积 ÷ 页面像素面积 ≥ 0.9** 在交付时再判一次（阈值与 `candidate_rules.json` 的
`page_like.page_area_ratio_min` 一致，避免两套口径打架）。被判为整页的图不进 `question_images`；
若该题因此没有图了，按"缺少有效题图"拒收——甲方要求每条必须有题图。

页面尺寸读取用 `np.fromfile + cv2.imdecode`，因为 `cv2.imread` 在 Windows 打不开中文路径，
而教材目录全是中文名。这个坑在测试里真实触发过。

### 4. H3⑩ / 备注 2 去重与跨批次身份

这是原来最大的一块空白：`id = f"{global_order:07d}"` 是**包内**序号，两个包必然都从 `0000001` 开始。

现在新增 `runtime` 同级的身份库 `delivery_identity.sqlite3`（跟随交付包根目录共享）：

- `samples(content_hash PRIMARY KEY, book_id, sample_id, created_at)` —— 跨批次内容指纹；
- `counter(sample_id)` —— 全局单调递增发号器，`BEGIN IMMEDIATE` 保证并发安全。

行为：

| 场景 | 结果 |
| --- | --- |
| 新内容，第一次出现 | 分配全局新号（`0000001`、`0000002`…），登记指纹 |
| 同一本书重新生成 | 复用原 `sample_id`，**样本 id 跨版本稳定** |
| 同内容出现在另一本书 | 拒收，错误写"与教材 X 已交付样本内容重复（备注2）" |
| 同一批次内两道相同题 | 第二条拒收，错误写"与第 N 条重复（H3⑩）" |

用 sqlite 而不是 JSON：1000 万条指纹的 JSON 全量读写在每次出包时都不可行。

### 5. H3⑥⑪ 噪声与乱码

交付前统一清洗：HTML 标签、HTML 实体、URL、表情符号、"版权所有/侵权必究/免责声明/扫码关注"之类句子。
题干预留检测 `U+FFFD`（替换符）与 `U+0000`，命中即拒收——那是 OCR 或编码失败的硬信号。

### 6. H3⑨ 均衡覆盖报表

新增 `k12_dataset/coverage_report.json`，按 `stage / subject / language / question_type / difficulty`
统计条数。**只出报表、不做闸**：单本书必然只覆盖一个年级，均衡是投放层按报表挑书的事，
让生成器拒收只会把正常数据也挡掉。

### 7. 标注入口：不再伪造题型

甲方枚举只有 9 个题型，但前端有 6 处在缺值时静默填 `'填空题'`，导致"没选题型"的题永远非空、
永远过校验、永远错标。已全部改为留空：

| 位置 | 改动 |
| --- | --- |
| `annotation-manager.js:1137` | 新建大题 `questionType = ''` |
| `main.js:2583` | `record.question_type \|\| ''` |
| `main.js:4779 / 4785` | `getQuestionInfo()` 不再兜底 |
| `data-manager.js:377` | `mainData.题型 \|\| ''` |
| `ui-manager.js` 题型下拉 | 增加"请选择"空项；删掉甲方词表外的"连线题""其他"（保留"口算题"，映射到计算） |

### 8. 标注入口：题干图 / 选项图可以分开标了

H3⑮ 要求 `question_image` 和 `option_images` 明确区分，但 `main.js:2644` 把 `image_kind` 写死成
`question_image`、`option_label` 写死成空串，交付侧那段 `option_image` 分支**永远走不到**，
`option_images` 恒为空数组。

现在图片区域编辑面板多了"图片用途"下拉（题干图 / 选项图 / 不导出）和"对应选项"（A-H），
双向映射都接通：`ui-manager` 采集 → `annotation.attributes` → `main.js` 写进 `illustrations`，
反方向 `image_kind/option_label` 也能回填到框上。

| # | 甲方要求 | 现状 | 判定 |

| 1 | JSONL / UTF-8 | `_write_k12_delivery` | ✅ |

| 8 | 解析含知识点/公式/推理/易错点 | 只查非空 | ❌ |
| 9 | 学段/学科/语言/题型/知识点均衡 | **`coverage_report.json` 出统计**，均衡靠投放 | ⚠️ |

| 12 | 不涉黄涉政涉恐暴力隐私歧视 | 无内容安全模型 | ❌ |
| 13 | PII 统一匿名化为 x | **手机/邮箱/身份证/社交账号全替换** | ✅ |
| 14 | 抽样原文 + OCR/公式/表格准确率报告 | 原图自动同步已有，**无准确率度量** | ❌ |
| 15 | 图片命名唯一、题干图/选项图区分 | 命名一贯；**新增"图片用途"标注，"选项图"可写进 option_images** | ✅ |

**统计：✅ 7、⚠️ 4、❌ 4。**

剩下 4 个 ❌ 的共同点：**都不是"加个 if"能解决的**。

- ⑦⑧ 答案准确性、解析质量 → 需要模型或人工抽查；
- ⑫ 内容安全 → 需要敏感词库 + 模型复核，纯词表误杀率太高；
- ⑭ OCR 准确率 ≥95% → 需要抽样集 + 人工标注真值，属于评测体系不是生成逻辑。

## 四、真实交付包为什么还是 0 条

```
runtime/delivery_packages 下 3 个 K12 包，dataset.jsonl 非空 0 个
BEFF9A63：21 题 → eligible 0
逐题拒收原因：缺少语言/学段/年级/学科/难度/知识点/题目文本/标准答案/详细解析/有效题图/题目尚未匹配答案
```

这四项（书级元数据、题图、题答配对、页面确认）**全部要在标注端由人填**。
这一轮做的是"填错了会被拦、填对了能出去"，不是"替人填"。

> 现在多了一条新风险：题型留空之后，**没选题型的题会被明确拒收**，而不是像以前那样被错标成填空题混过去。
> 上线后员工会第一次看到"缺少题型"的报错，这是预期行为，需要在培训里说清楚。

## 六、还没做 / 要你拍板

1. **`difficulty` 的 1-5 档位怎么映射**：`book_meta` 里有 `difficulty_scheme='1-5'`，标注端是 1-5 数字，
   交付要求"基础/中等/困难"。现在是**标注员直接选三档**，没做自动映射。若希望保留 1-5 录入再折算，
   需要给一组映射规则（1-2→基础、3→中等、4-5→困难？）。
2. **近似题检测**：目前只能抓"完全同文同选项同答案"。同题换图、改一个数字的近似题抓不到。
   要做需要 simhash / MinHash，属于独立模块。
3. **内容安全（H3⑫）**：要不要接词表？接了必然误杀一部分正常题（"毒品""战争"在化学、历史题里是正常词）。
4. **客户端更新包**：前端这 4 个 js 改了，必须发更新包员工才拿得到；`PaperFlow-Annotation` 不在 git。
5. **服务器引擎同步**：`review_tools/delivery_workspace.py` 必须手动 scp 到 `J:\papercutter\review_tools\`
   并核对 sha256，否则服务器仍跑旧契约（部署脚本不上传 `review_tools/`）。
