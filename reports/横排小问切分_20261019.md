# 横排小问按 x 递归切分（P1 收尾）

日期：2026-10-19
范围：`cut_questions_v4.py` 的小题切分层（L3）

## 1. 为什么做这一步

P1 修复后，21 页审计集里**只剩 1 个硬错误**：

```
20210126153256260570.jpg  塌缩1
「七、数一数，填一填。(9分）」印刷 3 题，只切出 1 题
```

其余 20 页全部零信号。所以这一步的验收标准是明确的：把那 1 个信号清零，且另外 20 页**一个字节都不许变**。

## 2. 根因：两道关都把它挡住了

把该块（2407×479）单独跑 OCR，结果是：

```
y=   7 x= 252  七、数一数，填一填。（9分）
y= 109 x= 878  2.
y= 112 x=1541  3.
y= 369 x= 413  有()个角
y= 373 x= 929  有( )个平行四边形
y= 386 x=1805  )个梯形
```

三个小问并排，y 坐标几乎相同（109 / 112 差 3px），题号 `1.` 整条被 OCR 漏读。`find_minor_boundaries` 有两道判据都拦在这里：

1. **左侧限制**：`left_limit = max(90, 宽×0.28) = 674`，而题号 2./3. 在 x=878 / 1541，直接按"正文数字碎片"丢弃。
2. **同一行去重**：相邻题号 y 差 3px 会被判成同一行，只保留靠左的一个。

于是 `boundaries` 最后只剩一个 `2.`，又因为"孤立题号且不是第 1 题 + 位置太靠上"被整体清空，退回整块 → 1 题。

## 3. 方案：XY-Cut 的横切步骤

### 3.1 放宽左侧限制，只对横排长条

```python
side_by_side_layout = crop_height < crop_width * 0.6
left_limit = crop_width if side_by_side_layout else max(90, int(crop_width * 0.28))
```

普通页面仍要求题号贴栏左缘；只有"高 < 宽×0.6"的横排长条放开，横向合法性交给下面的连续序列校验兜底。

### 3.2 同一水平带保留并排题号

```python
side_by_side = (
    candidate['style'] == 'primary'
    and boundaries[-1]['style'] == 'primary'
    and candidate['num'] == boundaries[-1]['num'] + 1      # 必须连续
    and candidate['x'] - boundaries[-1]['x'] >= max(120, int(crop_width * 0.12))
)
```

要求**编号连续 + 横向间隔足够**，所以选择题选项里的数字、正文里的小数仍然进不来。

### 3.3 按 x 分列，各列递归切分

`_side_by_side_columns()` 用文字块左缘做一维聚类（间隔阈值 `max(300, 宽×0.14)`），并且：

- 只统计**窄块**（宽 < 块宽×45%），跨列长题干不参与；
- 剔除**顶部横跨整块的标题**（y < 20% 且宽 > 块宽×20%），它只该跟第一列走；
- 其余各列从**标题下沿**开始，否则每列顶部都会带一截 `)分）` 碎片。

### 3.4 关键取舍：列区间允许重叠

这页的版面是"文字互相咬合"的：第 2 题题干 `有( )个平行四边形` 右缘到 x=1605，而第 3 题题号 `3.` 从 x=1541 就开始了 —— **水平方向真实交叉**，不存在贯穿的白缝。

任何单一硬切点都必然切掉一边。最终选择让列区间重叠：

```
列1 = [   0,  814]   列2 = [ 854, 1629]   列3 = [1517, 2407]
                    └──── 重叠 112px ────┘
```

代价是第 2 题图右侧带一个 `3.`、第 3 题图左侧带上题的末字"形"；换来的是**两道题的题干和插图都完整**。漏内容是硬错误，重复只是视觉瑕疵，这个取舍是明确的。

题号的归属按"列起点"而不是"列区间"判断，所以 `3.` 仍归第 3 列，不会在第 2 列内部再触发一次切分。

## 5. 连带修的两处排序

横排小问的 `_source_box` 顶边完全相同（都在 78），原来只按 y 排序的代码会拿到随机顺序：

- `cut_questions_v4.attach_shared_context_to_dependent_minors`
- `manual_annotation_workspace._indent_unit_hint`

两处都改成 `(y, x)` 双键排序。竖排场景 y 唯一，行为不变。

## 6. 数据链路改动

`attach_question_source_metadata` 原来把 `_source_box` 的 x 固定为整块宽，横切后会把邻题一起带出来。改为读 `_x_start/_x_end`（默认 0 / 块宽，老路径零变化）：

```python
local_x0 = max(0, int(minor.get('_x_start', 0)))
local_x1 = min(int(block_width), int(minor.get('_x_end', block_width)))
```
