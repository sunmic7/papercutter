## 三、部署中发现的两个真 bug

### 1. 诊断接口取错对象（阻断功能）

`server.py` 的 `GET /api/deliveries/<book>/diagnosis` 写成
`self.library.diagnose_delivery(...)`，但 `ReviewHandler` 只有模块底部注入的
`store` / `static_root`。线上点击「检查缺什么」会直接 400：

```
{"ok": false, "error": "'ReviewHandler' object has no attribute 'library'"}
```

原有 903 项测试全部直接调 `store`，没有一条走 HTTP handler，所以没被拦住。
修复为 `self.store.library`，并新增 `tests/test_review_http_routes.py`：用 AST 校验
handler 内所有 `self.<attr>` 只能来自类内定义、方法、`BaseHTTPRequestHandler` 继承成员
或 `store`/`static_root` 两项注入。全量 906 项 OK。

### 2. 未提交工程的教材抛裸 Errno

教材刚分配、员工还没标注时点「检查缺什么」，一路走到 `analyze_delivery` 才在
`load_project` 上炸开：

```
[Errno 2] No such file or directory: 'J:\...\central_projects\<book>\...'
```

改为在诊断入口先判断"工程不存在且无冻结快照"，抛中文提示：

> 该教材还没有提交过标注工程，暂时没有可分析的内容。请先在标注台完成标注并提交审核，再回来检查缺什么。

补 `test_diagnose_before_any_project_explains_instead_of_errno`。

## 四、验证证据

三层验收，全部在服务器上跑，用的是**部署后的真实代码路径**。

| --- | --- | --- |
| 引擎 + 服务层（隔离临时数据） | `_experiments/remote_delivery_deploy_accept_1106.py` | **31/31 PASS** |
| HTTP 全接口（临时实例 :18787） | `_experiments/remote_http_isolated_1106.py` | **18/18 PASS** |
| 线上 8787（真实生产库） | `_experiments/remote_http_accept_1106.py` | **8/8 PASS** |

关键结论：

- 员工只上传扫描件（冻结工程无本地根）时，服务器能复现指纹、裁图、写出合规
  `dataset.jsonl`；样本外层是 `{id, metainfo, data, source}`，`metainfo` 七项齐全。
- **跨批次去重真的生效了**：身份库落在交付根（`final-output/delivery_identity.sqlite3`），
  不再每版一份空库。这是本轮修复的核心 bug。
- 词表闸按预期拒收：`难度不在甲方词表内：简单` / `题型不在甲方词表内：单选`。
- 诊断不裁图、不改盘（图片数 3 → 3），优先读冻结快照，与生成口径一致。
- 交付预览四件套（题单/诊断/原始 JSON/题图）在 HTTP 层可用；标记可写可读可删；
  越界图片路径 400；未登录 401。
