## 二、可交付性检查：生成前就能看到缺什么

### 1. 新增只读分析函数

`review_tools/delivery_workspace.py` 新增：

```python
analyze_delivery(project_path, runtime_root, *, identity_path=None, project_document=None) -> dict
```

它与 `_write_k12_delivery()` **跑同一套校验**（`_k12_validation`、`_content_signature`、
`_vocabulary_errors`、整页图面积复查、包内去重、跨批次身份），但：

- 不裁任何图
- 不写任何文件
- 不分配 sample id（身份库只在文件已存在时以只读方式打开，避免诊断本身创建空库）

为了不复制关系构造逻辑，把 `sync_delivery_workspace()` 里的 question/answer 配对抽取为
`_relation_maps()`，写入与诊断共用，避免两边判定"已匹配"的口径分叉。

返回结构：

```json
{
  "book": {"book_id":"…","title":"…","fields":{…},"errors":["缺少年级"]},
  "total_questions": 21, "eligible_count": 0, "rejected_count": 21, "deliverable": false,
  "reason_summary": [{"reason":"缺少难度","count":21,"questions":["一1","一2"]}],
  "items": [{"page":1,"question_number":"一1","eligible":false,"errors":["缺少难度"]}],
  "sample_preview": [ {…第一条合格样本的完整 JSON…} ],
  "dataset_path": "…/k12_dataset/dataset.jsonl"
}
```

`reason_summary` 按错误文本聚合（每条最多带 5 个示例题号），操作员一眼看到"这本书主要缺什么"；
`book.errors` 单独列出书级缺失（语言/学段/年级/学科），因为那会让**每一道题**都被拒收。

### 2. 质量报告同步增强

`quality_report.json` 新增 `reason_summary` 字段（与 `items` 并存，字段只增不减），
生成后看报表也能直接看到聚合原因。

### 3. 服务端接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/deliveries/<book_id>/diagnosis` | `super_admin/admin/reviewer` | 审核进度 + 逐题缺失字段 |
| GET | `/api/deliveries/<book_id>/dataset?limit=20` | 同上 | 已发布 `dataset.jsonl` 前 N 条 + 拒收汇总 |

`CentralLibrary.diagnose_delivery()` 优先分析**冻结工程**（生成时用的就是它）：冻结快照的
`image_root` 在同步时被剥掉，所以先调 `_bind_delivery_source_roots()` 重绑服务器原图，
整页图面积判断才准确；重绑失败时降级为字段级诊断，不会因为缺图直接报错。

`delivery_dataset_preview()` 读 `current.json → path → k12_dataset/dataset.jsonl`，
只读不写，最多 100 条。

### 4. 页面

「生成JSON」页每行新增两个按钮：

- **检查缺什么**（所有未删除任务）：弹窗展示审核进度、检查依据（冻结/当前版本）、可交付条数、
  整本书元数据缺失、按缺少项汇总表、逐题明细（前 50 条）、以及第一条合格样本的完整 JSON。
- **查看 JSON**（生成成功的任务）：弹窗展示版本号、样本总数、数据集相对路径、拒收汇总，
  以及前 20 条样本的可折叠完整 JSON。

顶部说明与状态图例同步改写，帮助里也写清了这两个按钮能回答什么。

## 三、顺手修掉一个真缺陷：跨批次身份库落在版本目录里

原实现 `sync_delivery_workspace()` 把身份库固定在 `root.parent / "delivery_identity.sqlite3"`，
而服务器每生成一版都会把 `delivery_output_root` 指到自己版本的 staging 目录：

```
work_root/<book_id>/exports/<version>/staging/<book_id>   ← root
work_root/<book_id>/exports/<version>/staging/delivery_identity.sqlite3   ← 身份库
```

结果是**每个版本一份空库**，跨批次内容去重（甲方备注第 2 条）在生产上等于没生效。
本机测试因为多个工程共用一个 `delivery_output_root` 才碰巧通过。

修法：

- `sync_delivery_workspace(..., identity_path=None)` 新增显式参数，默认行为不变（本机兼容）；
- `central_library.generate_delivery()` 显式传 `final_root.parent / "delivery_identity.sqlite3"`
  ——`final_root` 是 `<交付根>/<book_id>`，其 parent 就是交付根，全站共享；
- `analyze_delivery()` 同样接受 `identity_path`，诊断查的就是生成时用的那本。

| 套件 | 结果 |
| --- | --- |
| `test_k12_delivery_contract.py` | 19 项 OK（新增 5 项诊断用例） |
| `test_central_library.py` | 21 项 OK（新增 2 项服务器诊断用例） |

| **全量** | **888 项 OK**（`python -m unittest discover -s tests -q`，227 秒） |

关键断言：

- 体检**不创建交付目录**（`runtime/delivery_packages` 不存在），且诊断的可交付条数与真实生成一致；
- 缺难度/知识点时 `reason_summary` 精确给出原因与题数；
- 书级缺年级进 `book.errors`，与逐题原因分开；
- 服务器拿到冻结工程诊断时 `project_source == "frozen"`，且体检期间没有 `current.json`；
- 客户端三处入口与两个后端接口都不存在。
