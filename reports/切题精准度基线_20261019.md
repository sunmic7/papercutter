# 切题精准度基线（零人工抽样）

日期：2026-10-19
样本：6 本书 × 每本 3 页自动抽样（共 21 张，其中 10 张是含题目的页面）
工具：`review_tools/cut_quality_audit.py`
原始数据：`reports/audit_baseline.jsonl`、`reports/audit_baseline_summary.json`

---

## 0. 一句话结论

**含题目的 10 张页面里，7 张存在硬错误；大题召回 40/45（88.9%）。**

错误不是散落的，集中在三个可单独修的形态：

| 形态 | 次数 | 现象 |
|---|---|---|
| 空壳块 | 2 | 大题标题被单独切成 9～13px 的碎片，正文又成了另一块 |
| 大题塌缩 | 4 | 题号明明印着 6～9 道，整块只切出 1 道 |
| 吞并 | 3 | 一个块里含 2 个以上大题 |

其中"空壳块"改动最小、收益最直接，建议作为 P1 的第一项。

---

## 1. 为什么不做人工标注

没有人力做逐题真值。改用**图像自带的印刷题号**当真值：

- 同一页跑两次 OCR：`ocr_page_structure`（生产口径，稀疏，只扫标题带和题号带）用来切块；`ocr_image`（整页，更全）只用来读"这页印了哪些题号"
- 两者独立，所以"生产口径漏掉了多少题号"本身也是可测的

**局限（重要）**：这个真值会漏报，不会误报。

- 整页 OCR 漏读某个题号时，会让"漏切/多切"的集合差看起来有错。实测第 7 张就被误报过一次（印刷 1～8，OCR 只读到 1、3、7、8）
- 因此集合差只作为 `diagnostic` 原始数据保留，**不进汇总**
- 汇总只统计几何或文本上无可辩驳的信号：块高异常、相邻块同一大题号、块内印刷大题数 ≥2、块内印刷题号 ≥3 却只切出 1 题

---

## 2. 指标

| 指标 | 定义 | 为什么可信 |
|---|---|---|
| 大题召回 | 印刷大题标题中，被识别成块标题的比例 | 大题标题 OCR 稳定，长度短 |
| 空壳块 | 块高 < 40px | 纯几何，无需真值 |
| 重复标题块 | 相邻两块大题序号相同 | 纯文本比对 |
| 吞并块 | 一个块内含 ≥2 个印刷大题标题（同时比 x/y） | 几何 + 文本双证据 |
| 塌缩块 | 块内印刷小题号 ≥3，却只切出 1 题 | 只在证据充分时触发 |
| 整页块（有据） | 块标题退化为"整页"，且块内首题号是 1 或含大题标题 | 已排除"跨页续题"这种正常形态 |
| 题号未识别 | `number_detected=False` 的题 | 内部信号 |

封面、版权页、答案页没有印刷题号，所有比率只在 `applicable` 页上计算。

## 4. 三类错误的具体样子

### 4.1 空壳块（最便宜可修）

```
金版卷王四年级 20210126153256260587.jpg
  blk2  「三、认真判断。（对的打"√"，错…」  高度 9px   ← 碎片
  blk3  「三、认真判断。（对的打"√"，错…」  高度 635px ← 正文
```

同一大题标题出现两次，第一次只有 **9px**。六年级那本同样位置是 **13px**。

标题行本身约 30～40px，9px 说明切点落在了标题字的中间：块边界被 `find_minor_boundaries` 返回的一个错误 y 值切在标题行上。后果是交付时多出一张"只有半行标题"的图。

**修法**：块高 < 40px 且与下一块大题序号相同 → 并入下一块。改动局限在 `split_page_into_majors` 出口，风险小。

### 4.2 大题塌缩（用户感知最强）

```
金版卷王四年级 20210126153256260579.jpg
  blk1  「二、填空。(20分）」高度 2141px，印刷题号 1,5,6,7,8,9，只切出 1 个
```

这一页是"期中达标检测卷"，左侧「二、填空」有 9 道题，题号 1～9 印得很清楚。整块只切出 1 道，意味着 8 道题会一起交付成一张长图。

同一本书第 9 张的「二、填一填」却能正常切出 1～11 共 11 道。差异在**题目行距**：这一页填空题每条占 1～2 行、行距很紧，`find_minor_boundaries` 的"位置、间距合理"判据把它们过滤掉了。

### 4.3 吞并

```
数学奥赛天天练 四年级：印刷 2 个大题，识别出 1 个块标题，另一个大题被并进同一块
全能测控 六年级下：印刷 6 个大题，只识别出 3 个
抢先起跑 四年级 image0000911B.jpg：一个块含 5 个大题（1~5）
```

`image0000911B.jpg` 是**答案页**（标题是「二、1.0124」「三、1.D 2.B 3.C 4.B」「四、略」），不该和题目页混在一起评估，这条样本应排除。另外两条是真吞并。

## 5. 顺带发现的性能问题

审计按页分段计时后，暴露出 OCR 的真实成本：

| 阶段 | 冷跑 | 缓存命中 |
|---|---|---|
| `ocr_page_structure`（结构扫描） | 45～70 秒 | 0.06～0.2 秒 |
| `ocr_image`（整页） | 80～95 秒 | 0.0 秒 |
| `split_page_into_majors` | 0.2～6 秒 | 同左 |
| `split_major_into_minors` | 18～62 秒 | 无缓存 |

单页冷跑合计 130～200 秒。这解释了此前"首次自动框题 147 秒"里的大部分：瓶颈不只在模型加载，**OCR 本身在 4897×3377 的对开扫描上就是这个量级**。

`split_major_into_minors` 的 18～62 秒来自跳号补救（`_recover_missed_minor_boundaries`）：它对整条跨全宽的条带做原生分辨率 OCR，而实际只采用左 28% 的题号。**把条带先裁到左 30% 再识别，预计可压到 1/3，且结果等价**——这是 P1 里性价比很高的一个优化，尚未实施。

## 6. 对 P1 排序的调整

原计划按"题号体系 → 跨页续题 → 答案页剔除"推进。数据显示应先修块边界：

| 顺序 | 修什么 | 依据 |
|---|---|---|
| **P1-1** | 空壳块并入下一块 | 2/10 页命中，改动最小，纯收益 |
| **P1-2** | 大题塌缩：放宽密排填空题的边界间距判据 | 4/10 页命中，用户感知最强 |
| P1-3 | 吞并：大题标题漏识别的补召回 | 3/10 页命中 |
| P1-4 | 跳号补救提速（裁窄条带） | 顺带解决 18～62 秒的切分耗时 |
| P1-5 | 题号体系扩展（`(1)`、`①`、`例3-1`） | 目前未成为主要错因，暂缓 |

每做完一项，用同一命令重跑这 21 张，对比上面那张总体表。

---

## 7. 局限

1. **样本只有 21 张、6 本书**，且集中在小学数学。统计上够用来定位形态，不够用来报"准确率"。
2. **答案页混入**：`image0000911B.jpg` 是答案页，被当成题目页评估，其 3 条错误应扣除。
3. **只测硬信号**，语义型错误（题号对但归属错、选项被切走）完全没覆盖。
4. 真值来自 OCR，OCR 本身有漏读，因此这份基线是**下限**：真实错误率只会更高。

## 8. 复现

```bash
# 抽样跑基线（追加写 JSONL，可断点续跑）
python review_tools/cut_quality_audit.py \
  --books-from reports/audit_books.txt --sample 3 \
  --out reports/audit_baseline.jsonl

# 汇总
python review_tools/cut_quality_audit.py \
  --summarize reports/audit_baseline.jsonl \
  --json-out reports/audit_baseline_summary.json

# A/B：关掉版面裁判再跑一遍，对比同一批指标
set PAPERFLOW_LAYOUT_ARBITER=0
python review_tools/cut_quality_audit.py --books-from reports/audit_books.txt --sample 3 \
  --out reports/audit_no_arbiter.jsonl
```

单页耗时 70～200 秒，21 张约 20 分钟。真值 OCR 结果有缓存，第二轮同批次几乎瞬时。
