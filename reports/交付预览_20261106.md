# 交付预览：把甲方版式的题目摆到浏览器里（2026-11-06）

## 一、先回答"要不要和「生成JSON」融合"

**结论：融合，作为「生成JSON」页的二级视图，不新增左侧菜单。**

理由按重要性排列：

1. **预览的数据源就是生成结果。** 没有 `current.json` 就没有可看的内容。独立菜单里，一本教材的绝大多数时间都是空页面，用户点进去只会看到"还没生成"。
2. **发现问题要能立刻回手。** 预览时看到某题图裁错，下一步动作是回到队列重试生成或看「检查缺什么」。同页两级视图，返回一次点击；独立菜单要跨页面跳两次，还丢筛选状态。
3. **侧边栏已经有 6 项。** 再加一项会让"哪一步该去哪"更模糊——审核在「审核任务」、生成在「生成JSON」，预览天然属于后者。
4. **融合不等于塞进表格。** 表格行只放一个「预览内容」入口，点进去是占满内容区的三栏工作台，与「审核任务」的沉浸式查看手感一致。

代价：预览的入口藏在任务表里，第一眼不明显。缓解办法是在副标题、状态说明、帮助文档三处都写明"生成后点预览内容"，并把原来那个只能看原始 JSON 的「查看 JSON」按钮直接升级成它——入口数量不变，能力变强。

## 二、页面长什么样

三栏，和审核中心同一个操作模型：

| 区域 | 内容 |
|---|---|
| 左栏 | 题目列表：题号、页码、题型、题干首行；有标记的显示橙色角标；支持"加载更多" |
| 中栏 | 甲方 K12 版式卡片：题型/难度/学段年级/学科/语言标签 → 题号与来源 → 题干 → 题图（可点开大图）→ 选项 → 选项图 → 答案（绿）→ 详细解析（浅蓝）→ 知识点 chips |
| 右栏 | 来源与归属（教材、编号、页/序、题号、内部题号、对应答案、交付版本）+ 审核标记 + 可展开的原始 JSON |

顶部还有：返回、书名与版本、数据集条数、生成时拒收条数（可展开原因）、版本下拉、搜索框、题型/难度筛选、`← →` 键盘翻题提示。

**关键一点：页面显示的就是交付包里的原文。** 题干、答案、解析、图片路径全部直接读 `dataset.jsonl` 和 `images/`，不重新生成、不重新裁图、不二次清洗。左侧看到第 3 条，就是客户拿到的第 3 条。

## 三、为什么要有「标记」

预览如果只能看，看完就忘，问题无法汇总，也无法交给标注员返工。所以每条支持写一句话标记，落在 `delivery_notes` 表里，绑定 `book_id + version + sample_id`：

- 审核员/管理员可写；
- 只能删自己写的，管理员可删全部；
- 换版本后旧标记仍按版本保留，不会串到新版本；
- 列表角标实时反映条数。

## 四、接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/deliveries/<book>/samples?offset&limit&query&question_type&difficulty&version` | 分页 + 筛选后的数据集条目，附带版本列表、筛选项、标记、拒收原因 |
| GET | `/api/deliveries/<book>/sample-image?version&path` | 鉴权取裁图，路径必须落在 `versions/<v>/k12_dataset/images/<file>` |
| POST | `/api/deliveries/<book>/notes` | 新增标记 |
| DELETE | `/api/deliveries/<book>/notes/<id>` | 删除标记 |

权限沿用 `DELIVERY_ROLES`（super_admin / admin / reviewer）加教材可见性判断；标注员拿不到预览。

图片接口做了三层限制：后缀必须是 jpg/jpeg/png、路径必须恰好是 `images/<文件名>` 两段、解析后的绝对路径必须仍在版本目录下。端到端实测 `../../current.json` 这类输入直接 400。

## 五、和「检查缺什么」的分工

两者不重叠，合起来才是完整闭环：

| | 检查缺什么 | 预览内容 |
|---|---|---|
| 时机 | 生成前（也可随时） | 生成成功后 |
| 数据源 | 审阅冻结工程的即时计算 | 已发布版本的 `dataset.jsonl` |
| 回答 | 为什么出不了包 | 出去的这个包对不对 |
| 输出 | 缺哪些字段、按原因聚合、逐题明细 | 一道一道的成品版面 + 标记 |
