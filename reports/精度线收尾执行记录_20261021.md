### 2.2 `enrich-prepare` 的真实行为

```json
首调 rebuilt = {"pages": 8, "frozen": 105, "skipped": 0}
二调 rebuilt = {"pages": 0, "frozen": 0,  "skipped": 105}
```

二次调用 `skipped=105` 与文档写的幂等预期完全一致。
**代价如实记录**：`rebuild_missing()` 在 `_enrich_prepare` 入口无条件执行、遍历全部 41 页，
所以一次调用就把全书 8 个有题框的页（含 27 个 `unlabeled` 草稿页里的题框）全部冻结并算了级别——
"我只确认了一页，为什么别的页也变了"是既定取舍，不是缺陷。

### 2.3 第 ④ 步：确认题目页（page_index=4，13 个题框）

```json
{"frozen": 0, "unchanged": 13, "stale": 0, "review_summary": {"L0": 0, "L1": 0, "L2": 13}}
```

`unchanged=13` 是重要证据：**同一输入二次冻结不重写**（`created_at` / `hash` / `page_index` 都不动），
补建与人工确认不会互相踩。

### 2.4 第 ⑤ 步：确认答案页 —— 本工程做不到

`b2897bcaf29a9936` **0 个答案页**，第 ⑤ 步无法执行，显式记为 `skipped: no_answer_pages`，不伪装成做过。
