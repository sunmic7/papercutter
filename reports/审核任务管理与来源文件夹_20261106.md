# 审核任务管理、来源文件夹与保存提速（2026-11-06）

这一轮解决四张截图反映的五个问题：状态"待重新提交"看不懂、保存到服务器很慢、
审核要一页页点、同一本教材在任务列表里出现多次、来源文件夹没有地方管理。

## 1. 「待重新提交」是什么意思，为什么会突然变成它

**含义**：这份审核快照提交之后，工作台里这本书的标注又被改过（框、文字、配对、
页码任一变化），快照已经不是最新内容。审结论记在旧框上没有意义，所以系统把它
作废，等标注员重新提交。旧快照留在"历史版本"里可查，但不能继续审。

**为什么刚提交就变成它**：原来的作废条件是"工程修订号变了"。可是工作台每存一次
都会把 `project_revision` 加一——切个页面、又存了一次同样的框也算。于是提交审核后
只要再触发一次自动保存，任务立刻作废；截图里 15:34:13 提交、15:35 就已经是
"待重新提交"，一条页面都没来得及审。

**改法**：作废判定改用**内容指纹**（`review_tools/online_review_sync.py`
`content_fingerprint()`，只覆盖审核能看到的字段：教材元数据、页面、题框、文字、
选项、答案、解析、配对、分组、插图框）。内容没变的保存不再作废任务；真的改了
内容才作废。

- `submissions` 表新增 `content_fingerprint` 列（自动迁移）。
- 快照里带上 `content_fingerprint`，服务端存下来；老客户端没有这个字段时退回
  "按版本号作废"，不会误判。
- `note_project_saved()` 比较指纹：一致 → 保留任务；不一致 → 照原样作废。

**界面**：详情页顶部的黄条改成完整解释（含修订号），任务列表的"状态与统计口径"
里也补了一段；使用帮助里加了同样一段。

## 2. 保存到服务器很慢

根因不是网络，是**书级锁被后台任务占住**：

`CentralLibrary.operate()` 里每个保存都要拿 `book_locks[book_id]`。
而"实时样例题库"每存一次就在 20 秒后后台重算整本书——它拿的是**同一把锁**，
重算期间要读全部页面、裁图、生成 K12 数据集，几十秒。这段时间里员工的每次
保存都排在它后面，界面上就是"正在保存到服务器…"一直转。

修法：

- 新增 `ready_locks`，实时样例题库重算只和自己串行，不再抢书级锁。
- 重算只在"读一次工程文件"的瞬间拿书级锁，重活（裁图、算数据集）在锁外做。
- `operate()` 记录等待书级锁的耗时，超过 1.5 秒往 stderr 打一行
  `[book-lock] <book_id> 等待书级锁 N ms（operation）`；保存的耗时也写进
  `central_project_saved` 审计事件的 `elapsed_ms`。下次再"慢"，能直接对上是谁在占锁。

## 3. 审核界面的快捷按钮

- 结论面板顶部加一排**一键结论**：通过 / 需精修 / 退回重标。点完即保存并自动跳到
  下一张待审页，不用再"点单选 → 点保存 → 点下一页"。
- 详情页顶部加**一键通过剩余 N 页**：只处理还没审的页，已经点过退回或精修的页
  不会被改（这一点有单测锁定）。
- 服务端新接口 `POST /api/submissions/<id>/pages/decide`（`decide_pages()`）：
  一个事务里批量写结论、重算整本状态，整本放行时照常自动排队生成。
- 单页审核的收尾逻辑抽成 `_settle_submission()`，单页与批量走同一段统计。

## 4. 同一本教材重复提交只显示一条 + 管理员批量管理

- `latestTaskPerBook()`：默认每本教材只显示**最新一次提交**；KPI 卡片、状态分布图、
  分页都用去重后的行，所以卡片上的数字和点进去的行数一致。列表顶部会提示
  "已合并同一教材的 N 条旧提交"。
- 想看全部：筛选切到"历史版本"或"全部含历史"，不做合并。
- 管理员右上角新增**批量管理**：勾选后可以批量指派审核员
  （`POST /api/submissions/batch/assign`）、批量删除、进回收站批量恢复
  （复用 `POST /api/deliveries/tasks/batch`）。删除仍是软删除——冻结工程、
  审核结论、已生成的交付文件都保留。

## 5. 来源文件夹管理（派发教材任务的新子菜单）

- "派发教材任务"页顶部拆成两个子菜单：**教材目录**（原来的列表）/ **来源文件夹**。
- 原来的「添加教材文件夹」按钮已删除，新增教材走来源文件夹页。
- 来源文件夹页：列出内置根目录 + 所有已登记目录，显示教材数、最近扫描时间、
  目录是否还能访问；每行可编辑（名称、备注、路径）、立即扫描、移除登记。
- **改路径**专门为"整盘搬迁"设计：填了新路径就只改登记（`library_book_sources.path`、
  `textbook_library.relative_path` 一起挪），不移动、不删除任何原图。旧路径已经
  不存在时也给改，因为搬完盘旧路径本来就没了。
- 移除登记只是不再扫描这个目录：教材、原图、标注、审核记录全部保留。
- 新接口：`GET /api/library/sources`、`POST /api/library/sources`、
  `POST /api/library/sources/scan`、`POST /api/library/sources/remove`（仅审核员及以上）。
- `library_scan_folders` 表补了 `label/note/created_at/updated_at/last_scan_at/updated_by`
  六列（自动迁移），扫描时会更新 `last_scan_at`。
